# LIEU_Senario.glb — 형상·계층·부품 해석

> **중요한 구분**: `형상으로 확인` / `유력한 기능 추정` / `미확인 실물 제약`. 본 문서는 GLB의 정적 CAD 메시를 분석한 것이며, 제조용 조립도·모터 데이터시트·전장 회로도를 대체하지 않는다.

## 1. GLB 정량 분석

| 항목 | 확인 결과 |
|---|---|
| 전체 glTF 노드 | **144개** |
| 실제 메시가 연결된 노드(인스턴스) | **61개** |
| 고유 glTF 메시 | **38개** |
| 재질 | **4개** (스틸 사틴, 어두운 불투명 재질 2종, 백색 에나멜) |
| embedded texture | 0개 |
| glTF animation / skin | 0 / 0개 |
| 씬 최상위 노드 | `Total_Ass'y_LIU v21` (**142**), `Rail` (**143**) |
| 축·크기 단위 | GLB 월드 좌표 기준 **Y-up, meter** (Fusion 내보내기 계층 스케일 포함) |

- **+X**: 로봇 눈이 놓인 대략적인 전면 방향; **-Y**: 바닥 투사 방향의 기본 가정; **Z**: 좌우 방향.
- 원본 모델의 노드는 일체형 어셈블리처럼 정적으로 배치되어 있다. **관절 제약·엔코더 좌표·모터 제어 채널은 GLB에 저장되지 않았다.**
- `Rail`은 `Total_Ass'y_LIU v21`의 자식이 **아닌 독립 루트 노드**이므로, 레일은 고정하고 로봇만 움직이는 리그를 만들 수 있다.
- 모든 로봇 부품의 `localTransform`은 원본 CAD의 크고 작은 계층 스케일을 가진다. **노드 로컬 translation을 mm처럼 임의 편집하지 말 것.** 월드 변환행렬을 사용해야 한다.

| 부위 | GLB에서 측정한 값 | 의미·한계 |
|---|---:|---|
| 도넛 하부 외경 | 약 **260 mm** | 메시 AABB X/Z ≈ 260mm; 조립·제작 공차는 별도 |
| 도넛 상부 외경 | 약 **258 mm** | 메시 AABB X/Z ≈ 258mm |
| 중앙 기둥 폭 | 약 **60 mm** | 원통 본체 메시 범위 |
| 레일 길이 | 약 **612.4 mm** | **이동 가능 거리 612mm가 아님** |
| 레일 단면 외곽 | 약 **68.5 × 68.5 mm** | 메시 바운딩 박스, 규격 인증 불가 |
| 중앙 NeoPixel 외경 | 약 **65.6 mm** | 모듈/PCB 포함 메시 외곽, LED 중심 반지름은 29.4mm |
| 틸트 회전축 양측 중심 | 대략 `(0, 0.020, ±0.0405)m` | 메시 AABB 중심, 관절 중심 확정값 아님 |

## 4. LED 픽셀을 모델에서 실제 추출한 결과

### NeoPixel: 24채널의 실제 기하

- GLB 노드 **133**의 한 메시 안에 PCB와 LED 칩 형상이 합쳐져 있다. **GLB 노드 24개가 아님.**
- 삼각형 연결 요소를 분해해 24개 칩의 중심을 식별했다.
- 중심선 반지름: **29.4mm**. 각도 간격: **15°**.
- `config/LIEU_LED_Calibration.json`의 `ring24.pixels[]`에 각 픽셀의 실제 **월드 좌표(m)**가 모두 들어 있다.
- `virtualIndex` 0은 **world +X** 방향, 1은 **+X에서 +Z로 15°** 전진하는 가상 시뮬레이션 번호다. **하드웨어 DIN 방향/LED 0번은 미확인**.
- `LED 쉐이드`(노드 17)는 LED 위의 확산 구조다. 원본 메시 전체를 한꺼번에 발광시키면 픽셀별 밝기가 구현되지 않는다.

### 8×8 눈: 좌우 각 64개 실제 기하

- 보드 한 개의 `Body2.007` (**8**)과 미러 보드 `Body2` (**13**)의 연결 요소마다 LED 발광 칩이 **64개**씩 들어 있다.
- `config/LIEU_LED_Calibration.json`의 `eyes[0].pixels`, `eyes[1].pixels`에는 128개 전부의 **위치·row·col**이 있다.
- 카메라가 **+X측에서 -X**를 보고 **+Y가 위**라고 가정하면 `+Z` 보드는 화면 왼쪽, `-Z` 보드는 화면 오른쪽이다. 실제 배선 행/열 방향과 I2C 주소는 검증 필요.
- 눈 모듈 이름은 **HT16K33**이며 이 계열은 일반적으로 단색 LED 매트릭스 구동에 쓰이지만, 이 실물의 발광색과 wiring은 GLB만으로 확정할 수 없다. 웹은 비트맵 픽셀 제어를 기본으로 하고 RGB 눈 연출은 별도 '가상 전용' 옵션으로 격리한다.

## 6. 원본 메시 연결에 관한 구현 경고

1. **Three.js GLTFLoader 이름 정규화 가능성**: 원본 glTF 노드 이름은 공백/특수문자를 포함한다. 가능한 경우 `gltf.parser.associations`의 노드 인덱스를 사용하고, `getObjectByName()`은 이름 정규화 검증 후 보조 수단으로 사용.
2. **노드 인덱스 ≠ 메시 인덱스**: 144개 노드 중 실제 렌더 메시는 61개이며, 38개 메시가 인스턴싱된다. `nodeIndex`를 기준으로 조작 시스템 바인딩.
3. **복합·음수 스케일**: 특히 `Rail`에 음수·비균일 스케일이 존재한다. 메시의 rest `matrixWorld`를 보존하고 월드 공간 동작행렬을 곱해 표시하면 안전하다.
4. **기계적 조인트 정의 없음**: 시뮬레이터는 '외관적으로 그럴듯한 리그'와 '실제 모터를 재현한 리그'를 명확히 분리한다.
5. **원본 재질에 emissive 없음**: 별도 실시간 렌더용 발광층, 보드 픽셀, 투사 쉐이더, 조명 효과를 구현해야 한다.

## 7. 참고 파일

- `config/LIEU_GLB_Node_Manifest.json`: **144개 전체 노드**, 상위 그룹, 부모/자식, 로컬 TRS, 각 메시의 월드 변환행렬·월드 AABB·vertex/triangle 수 및 재질까지 포함.
- `config/LIEU_LED_Calibration.json`: 24 ring + 좌우 각각 64 eye 픽셀의 **실제 CAD 기하 좌표** (하드웨어 인덱스 순서 아님).
- `config/LIEU_Simulator_Config.json`: 제어 채널·임시 프리뷰 리그·미확인 하드웨어 파라미터.
